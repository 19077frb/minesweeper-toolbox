# 扫雷工具箱 / Minesweeper Toolbox

双击 **启动程序.bat**，通过窗口顶部的 **PB/TOP5**、**自动上传录像**、**金羊杯文件筛选及成绩计算**、**CSV合并** 四个功能页切换。在 PB/TOP5 中添加多个输入文件夹，选择输出文件夹，点击“开始整理”。环境已用 uv 创建在 `.venv` 中，不需要打开 Excel。

四个功能位于同一窗口，切换页面保留各自的选项、任务进度和日志。共同选项统一使用“递归子文件夹”，共同路径按钮统一使用“选择文件夹…”，取消按钮均为“取消”。

所有功能的输入会自动保存为 `data/` 文件夹中的普通 JSON：

- `settings.json`：PB/TOP5 的输入文件夹列表、输出文件夹、递归、重命名、完成度校验及线程数。
- `upload_settings.json`：自动上传的输入文件夹、账号、密码、递归及跳过已上传选项。按用户要求，密码也以普通文本保存在此 JSON 中；界面仍以圆点显示，不写入上传日志。
- `gsc_settings.json`：金羊杯输入文件夹列表、输出文件夹、届数、标识后缀、起止时间、时间依据、递归、完成度校验及基准值。
- `csv_merge_settings.json`：CSV合并的输入文件列表、输出文件、整行去重、排序及输出编码。
- `app_settings.json`：上次选中的功能页。

修改后约350毫秒自动保存，关闭程序时立即补存，无需先点击“开始”。即使表单尚未填完也会保留，下次启动原样恢复；移除文件夹也会同步保存。采用临时写入后替换的方式更新 JSON，避免写入中断破坏原设置；临时文件正常完成后自动移除。旧版已保存的字段继续兼容，新增字段使用默认值。

**程序永不修改录像内容。** 源录像仅以只读模式打开；重命名仅改变文件名，不往 AVF 内写入 STNB 或任何其他数据。导出以独占创建方式写入新副本，不覆盖已有录像，并在复制时用 SHA256 验证字节内容与扫描时一致。

默认递归扫描 `.avf` 文件，直接重命名输入录像。可以取消“重命名输入录像”，此时只解析并复制，输出的录像仍使用标准新名称。每次运行建立独立结果目录，不覆盖上次结果。输出目录可以放在输入目录内，扫描会自动跳过它。目录联接和符号链接不递归进入。

**“校验完成度”默认关闭**：关闭时不调用局面推演，所有可正常读取的录像都按 completion=100% 计算 STNB，并参与 PB 和 Top5 筛选。勾选后才启用下文的胜利校验、用户确认清单及待核验处理。该选项会随其他设置保存。切换模式时缓存隔离：勾选校验后不会把之前“假定完成”的缓存当作已校验成功。

## 计算规则

- 参考 PB-master 的 `rename.c` 读取原始内容，不依赖现有文件名。兼容其中的 NF/FL 判定：出现移动、左键按下、左键松开、指定双键松开以外的鼠标事件时归 FL。
- PB：按“分类 + 级别 + 3BV”分组，取最短时间的一份录像；不按玩家区分。自定义局与原版一致，只按 3BV 分组，不进一步区分盘面尺寸。
- Top5：各分类、各级别内，time 用时升序、bvs 实际 `3BV / time` 降序、stnb 分数降序，各取五个不同的录像。并列按路径排序稳定取五份，不扩展至五名以外。字节完全相同的副本只参与一次排名。
- **初级 Top5 要求 3BV ≥ 10**，适用于 FL、NF、ALL 的 time、bvs、stnb 全部榜单；初级 PB 仍覆盖所有 3BV，中级和高级不增加此限制。
- **启用“校验完成度”时**，所有 PB 和所有 Top5 只收录确认成功完成的录像。通过 ms-toollib 推演复现胜利，或依据用户明确确认的录像内容 SHA256 清单判断；不只凭文件名。默认不校验时，一律按完成度100%处理。
- ms-toollib 对部分成功的 Arbiter 录像不能正确复现，故其 `is_completed=False` **不能直接解释为录像未完成**。这类录像标为“完成状态待核验”，写入 `needs_review.csv`，暂不排名，不声称真实完成度是多少。
- `confirmed_completed.json` 保存用户已确认完成的录像哈希及确认依据。本次原先误报的11份已按用户确认全部改为100%，重算STNB，校验内容哈希一致。改名、复制不会影响哈希确认；修改内容后原确认不再适用。没有将所有解析失败录像一律当作成功。
- `qg = time^1.7 / bv`；`STNB = sqrt(completion) × 常数 / qg`。初级、中级、高级常数分别为 36、162、435；成功录像或关闭校验时 completion=1。开启校验后的待核验录像 STNB 标为 NA，不生成虚假的低分。
- 文件名：`级别_NF或FL_时间_3BV=数字_3BVs=数字_STNB=数字_玩家.avf`。时间保留百分秒；3BVs 与原版一致向下截取两位小数；STNB 显示三位小数，**排名使用未舍入的实际值**。
- 用户未指定自定义局的 STNB 常数，故此类录像标记 `STNB=NA`，不生成 STNB 榜。
- 同名时增加 `_(001)` 等后缀，避免覆盖输入录像。重命名日志含 planned/done 两种记录：恢复或核对时以 done 为准。

## 进度与性能

后台线程执行，界面显示扫描录像总数、处理数、改名数、无需改名数、缓存命中数、级别+3BV 分组数、PB 筛选/复制数、Top5 目标/复制数、待核验数、无效数、警告数、耗时和处理速度。Top5 目标数在解析结束后确定；PB 总数包含三个分类，因此同一录像可能分别出现在 FL/NF 和 ALL 中。

批量并发读取、字典筛选 PB、每榜只保留五项候选。SQLite 保存解析后的元数据，以路径、大小、纳秒修改时间和解析版本验证缓存，重复整理时复用。输入内容变化会重新解析；如果用外部工具修改文件却保持大小和修改时间均不变，请删除 `metadata.sqlite3` 后重新运行。缓存不保存录像副本。

取消后保留已经完成的改名及复制，写出报告；等待任务停止后可关闭窗口。日志窗口最多保留约 1500 行，完整警告保存在 `warnings.txt`。

当前排名来自**选定输入文件夹中的本地成功录像**，不再读取 Excel 或推断其他电脑上的历史 Top5。实际复制时文件消失/无权限等会记录 warning；某个已有榜单不足五份也会记录 warning。损坏和不支持的 AVF 会单独记录并跳过。

## 自动上传录像

重新启动程序，通过顶部功能栏切换到 **自动上传录像**。选择输入文件夹、输入雷网账号密码，点击 **开始上传**。“递归子文件夹”默认开启，也可关闭。点击“使用本次整理结果”可以直接使用 PB/TOP5 的最新输出文件夹，也可以自行选择其他文件夹。切换功能页不会弹出新的程序窗口。

实现参考 `D:\saolei\自动上传\upload.jar` 中的登录与上传流程：先 POST `/player/Action/Login_Action.asp`，复用 Cookie，再逐个 POST `/Video/Action/Upload_Action.asp`。上传表单字段与旧工具一致，NF 传 `Video_IsNoFrag=1`、FL 传空值；标准级别为 Beg、Int、Exp。新功能不依赖 Java，不调用旧批处理，也不会从旧批处理自动读取密码。

目前旧工具的 HTTP 接口可访问，HTTPS 连接检查失败，因此界面明确注明 HTTP 未加密。账号密码仅发送至所显示的雷网站点；拒绝跨站点重定向。按用户要求，账号密码及文件夹选项自动保存到本机普通 JSON，切换功能页或重启后均可恢复；密码不写入命令行或上传日志。

- 仅上传标准初、中、高级 `.avf`，与旧工具一致；自定义局跳过。其他文件不会发送。PB/Top5 的 3BV 限制不影响上传功能，所选目录的标准录像均进入上传队列，由网站验证是否可收录。上传只读取必要元数据，不做本机完成度推演。
- 录像只读、不改名；提交的是完整原始 AVF 字节，不向录像内添加数据。日志记录源文件 SHA256。
- 每批相同内容只提交一次，所以选中含有 FL/NF/ALL、PB/Top5 多份副本的结果目录时，不会逐份重复上传。
- 默认跳过本机历史中该账号已经“上传成功”或“网站已存在”的相同内容；可以关闭该选项。历史保存在 `upload_history.sqlite3`，并非向网站查询的完整历史。
- 顺序上传，不对网站并发提交；支持取消，当前请求最长等待25秒。整理任务与上传任务不能同时执行，以免输入文件名在上传期间变化。
- HTTP 200 不等于成功。只有明确的成功/重复响应才计入对应状态。超时、连接中断、无法识别的响应标记“待确认”，不自动重试，避免服务器已收录后再次提交。密码错误或无法取得登录后的上传表单会停止整批。
- 网站返回 `parent.location.href='/Video/Upload_OK.asp';` 同样表示上传成功，程序已支持这种真实响应，后续会正常计入成功并保存上传历史。
- 每次生成独立的 `data/upload_reports/Upload_日期时间/`，其中 `upload.csv` 包含逐文件状态和网站响应摘要，`summary.json` 为汇总。源文件夹不写入上传标记，通过上传页的“打开报告文件夹”查看。

已用本地模拟HTTP服务器验证请求字段、登录Cookie、NF/FL值、原始文件字节、去重、历史跳过、密码脱敏及错误处理；未用真实账号向雷网提交录像。若网站接口发生变化，会停止或显示待确认，不把未知响应记作上传成功。

## 金羊杯文件筛选及成绩计算

“成绩记录”页仿照 GSC_calc_1.0.4 的彩色矩阵：左侧初级Top20，右上中级Top12，右下高级Top5；保留淡黄色表头、黑色格线、30档成绩配色、原始颜色阈值及深色格白字。底部显示总计、平均、T.37、B.37、BPP20、IPP12、EPP5、PPP37。鼠标移到实际成绩上可查看录像信息，缺项明确标注为补位值。可选择75%至150%显示比例，自动保存设置。

计算结束后自动切换到成绩记录；“打开已有成绩…”读取同一结果目录内的 `成绩.json` 与 `TopX.csv`，也可点击“查看最近成绩”恢复当前届数最近的结果。HTML报告沿用同一矩阵和颜色，支持浏览与打印。展示过程仅读取已有报告，不重新扫描或改动录像。

第三个功能页支持输入多个文件夹、时间区间、标识后缀、金羊杯届数和输出文件夹。填写后点击“开始筛选及计算”，结果位于 `输出文件夹/金羊杯届数/计算_日期时间/`，例如 `金羊杯26/计算_20261017_.../`。重复计算保留之前的结果。

规则根据本地 `GSC_calc_1.0.4.exe` 中的 `mymainwindow.get_sorted_data`、`clear_data`、`calc_grid` 字节码及其配置核对，未执行原程序。读取录像内部数据，不依赖现有文件名，也不要求先生成 CSV。

- 时间可选择“录像内记录时间”（默认）或“文件修改时间（原工具）”。以本机本地时间解释，输入 `YYYY-MM-DD HH:MM:SS`；区间包含开始和结束整秒。录像内记录时间取 AVF 开始时间戳，避免复制或下载引起的文件修改时间变化。原工具从录像文件夹统计时使用文件修改时间；该模式可用于对照。
- 标识后缀与 AVF 内部玩家标识的末尾匹配，区分大小写，例如填 `G52667`，不会误匹配文件名中的其他文字或位于标识中间的字符串。
- 金羊杯合并 FL/NF，不按玩家进一步分组。**筛选和导出初级参赛录像不设3BV门槛**，符合时间与标识后缀的初级录像（含3BV<10）均保留。**计算初级Top20成绩时仍要求3BV≥10**，低于10的录像不参与Time、3BV/s、STNB排名。中级≥30、高级≥100的既有筛选与计分门槛保持不变。自定义局不纳入。`参赛录像.csv` 的 `ranking_eligible` 列标记是否参与TopX。
- Time 升序、实际 3BV/s 降序、STNB 降序独立排名，分别取初级 Top20、中级 Top12、高级 Top5。同一录像可以同时进入不同指标榜单；字节完全相同的副本只计一次。STNB 沿用 36、162、435 常数，不提前舍入用于排名的值。
- “校验完成度”默认关闭，按100%计算；开启时复用现有完成度校验与用户确认规则。待核验录像会记录警告并排除。
- 每级别每项指标分别给出合计与平均。T37 为三档 Time TopX 合计之和；B37 为三档 3BV/s TopX 合计之和。
- PPP37 使用原工具 NT20.5 归一化：设各级别 TopX 平均值为 T、B、S，基准值为 T₀、B₀、S₀；`Pₑ₀ = Bₑ₀×Sₑ₀/Tₑ₀`。`BPP20=(B×S/T)/(B₀×S₀/T₀)×Pₑ₀`，IPP12 同理；`EPP5=B×S/T`；`PPP37=(BPP20×IPP12×EPP5)^(1/3)`。
- NT20.5 基准默认读取原工具旁的 `gsc_calc_1.0.ini`；缺失时使用已核对的默认值：初级 `(1.355, 9.245, 230)`，中级 `(8.371, 6.128, 177.9)`，高级 `(34.08, 4.860, 157.9)`。每次报告会记录实际使用的基准，可在 `gsc_settings.json` 的 `baseline` 中配置。
- 不足 TopX 时，遵循原工具补位规则：初、中、高级缺少的 Time 项分别补10、60、240秒，3BV/s、STNB补零，分母仍为20、12、5。报告与界面明确标记“暂定：局数不足”，不会把缺少的局数假装成真实录像。

输出包含 `参赛录像/级别/` 下的全部符合条件录像，以及 `TopX/级别/time、bvs、stnb/` 下各榜单的录像。`参赛录像.csv`、`TopX.csv` 记录原路径、筛选时间、SHA256和导出路径；`成绩.csv`、`综合成绩.csv`、`成绩.json`、`成绩.html` 保存成绩，`warnings.txt` 保存异常。点击“查看成绩”可打开HTML报告。

**源录像只读、不改名、不改内容**；复制沿用独占创建和SHA256校验。运行时显示扫描/处理总数、匹配数、排除原因、复制数和TopX进度。四个功能可随时切换查看，但互斥运行，关闭窗口时先取消当前任务。

## CSV合并

第四个功能页移植自 `D:\saolei\merge_csv\main.py`。添加两个或更多输入CSV，选择输出CSV，点击“开始合并”。支持一次选择多个文件；列表顺序即合并顺序。默认预填旧脚本的 `stats_csv.csv`、`stats_csv_PC.csv`，输出为 `stats_csv.csv`，但不会自动执行或改写它们。

- 默认按完整行去重，与原脚本的 pandas `drop_duplicates` 一致；日期时间相同、但其他字段不同的记录会保留。
- 默认按 `mode` 的 BEG、INT、EXP 顺序，然后按 Year、Month、Day、Hour、Min、Sec 升序排列。同级别同时间的记录保留输入中的相对顺序。
- 输入须为Arbiter统计CSV，前七列是 `Day,Month,Year,Hour,Min,Sec,mode`。不同文件后续的附加列按原脚本的合并方式取并集；缺少的单元格留空。遇到未知级别时保留其原值并排在末尾，日志记录提示，避免原脚本分类转换把级别变成空值。
- 可关闭“整行去重”或“按级别、录像时间排序”。输入支持UTF-8及UTF-8 BOM，输出可选择UTF-8（原工具格式）或UTF-8 BOM（便于Excel识别）。
- 输出允许与一个输入文件同名，和原脚本用法一致。替换前自动将旧输出备份为 `文件名_before.csv`。如果已存在该备份，则创建带时间和序号的新备份，**保留原备份**。其他输入文件不变。
- 写入采用临时文件后替换。校验、写入失败或提交前取消时，不替换旧输出；临时文件会清理。文件在读取或准备替换期间被外部修改时停止，避免覆盖变化。
